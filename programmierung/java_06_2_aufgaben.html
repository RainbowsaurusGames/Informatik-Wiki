Speicher & Grenzen

Elementarer Datentyp Anzahl der Bits (und Bytes) Kategorie & Kurzinfo

A2 Was ist ein Variablenüberlauf, welche Auswirkungen hat er und wie ist er vermeidbar?

Was ist ein Variablenüberlauf (Overflow)?
Ein Variablenüberlauf tritt auf, wenn das Ergebnis einer arithmetischen Berechnung den maximal darstellbaren Speicherbereich (Wertebereich) des verwendeten Datentyps überschreitet.

Auswirkungen auf eine Berechnung:
Java wirft bei einem Ganzzahl-Überlauf keine Fehlermeldung! Stattdessen kippt der Wert durch die interne Zweierkomplement-Darstellung wie bei einem alten Kilometerzähler vom höchsten positiven Wert direkt auf den kleinsten negativen Wert um. Beispiel bei int: Rechnet man 2147483647 + 1, lautet das Ergebnis plötzlich -2147483648. Folgeberechnungen (z. B. Kontostände, Preise oder Array-Indizes) werden dadurch komplett verfälscht.

✅ Wie lässt sich ein Variablenüberlauf vermeiden?
  1. Größeren Datentyp wählen: Statt byte oder short direkt int verwenden; wenn Werte die 2-Milliarden-Grenze erreichen können, auf long (64 Bit) oder die Klasse BigInteger (unbegrenzte Größe) ausweichen.
  2. Wertebereich vorab prüfen / sichere Methoden nutzen: Ab Java 8 bietet die Standardbibliothek Methoden wie Math.addExact(a, b) oder Math.multiplyExact(a, b) an. Diese erkennen einen Überlauf sofort und werfen gezielt eine ArithmeticException, statt heimlich mit falschen negativen Zahlen weiterzurechnen.

A9 Aufgabe 9: Berechnungen mit float und der Konstante Math.PI 

float f = 0.5f;
int a = 10 * f;
System.out.println((float) a);

Ergebnis: ❌ Fehler (Compiler-Error)

Grund: Der Ausdruck 10 * f multipliziert einen int mit einem float. Das Ergebnis der Rechnung ist vom Typ float (5.0f) und kann nicht ohne expliziten Cast (int) in der int-Variablen a gespeichert werden. 

float radius = 18;
float umfang = 2 * Math.PI * radius;
System.out.println(umfang);

Ergebnis: ❌ Fehler (Compiler-Error)

Grund: Math.PI hat den Datentyp double (64 Bit). Sobald ein double in einer Rechnung vorkommt, wird das gesamte Ergebnis zu einem double. Ein 64-Bit-double passt aber nicht ohne Cast in die 32-Bit-Variable float umfang!

Aufgaben 5 bis 8

3. Zeichenkodierung (char), Unicode-Rätsel & Strings

Text & Zeichen

A5 Zeichenkodierung & Bit-Breite von char

Dem Datentyp char liegt in Java der Unicode-Standard (konkret UTF-16) zugrunde. Zur Darstellung eines einzelnen Zeichens werden exakt 16 Bit (2 Byte) benötigt. Dadurch lassen sich $2^{16} = 65.536$ verschiedene Zeichen direkt abbilden (die ersten 128 Zeichen von 0 bis 127 sind dabei identisch mit der klassischen ASCII-Tabelle).

A7 Ist String ein elementarer Datentyp?

Nein! String ist kein elementarer (primitiver) Datentyp, sondern ein Referenzdatentyp (eine vollwertige Klasse aus dem Paket java.lang). Das erkennt man schon an der Großschreibung von String. Eine String-Variable speichert nicht den Text direkt, sondern eine Speicheradresse (Referenz) auf das String-Objekt im Heap-Speicher.

A6 Unicode-Praxis: Den Programmcode vervollständigen, um „BFW“ auszugeben

In der Unicode-/ASCII-Tabelle beginnt das große lateinische Alphabet beim Buchstaben 'A' mit dem Dezimalwert 65 (Hexadezimal 0x41). Durch einfaches Abzählen (oder Nachschlagen) erhalten wir die Werte für B, F und W und wandeln die int-Zahlen per (char)-Cast in echte Buchstaben um:

'B' Dezimal: 66
Hex: 0x42
'F' Dezimal: 70
Hex: 0x46
'W' Dezimal: 87
Hex: 0x57

A8 Escape-Sequenzen: Welche Ausgabe erzeugt die Anweisung in Aufgabe 8?

Aufgaben 10, 11 & 12

4. Inkrement & Dekrement: Präfix- vs. Postfix-Notation

Prüfungsklassiker

A11 Erläuterung der „Präfix- und Postfix-Notation“ (Aufgabe 11)

Steht ++ oder -- ganz allein in einer Zeile (faktor++;), ist es völlig egal, ob die Zeichen vor oder hinter der Variablen stehen. Steckt der Operator jedoch mitten in einer größeren Rechnung oder Zuweisung, entscheidet die Position über die Reihenfolge:

1. Präfix-Notation (++faktor / --faktor)

„Zuerst ändern, dann rechnen!“
Die Variable wird sofort um 1 erhöht, und dieser neue, erhöhte Wert fließt direkt in die aktuelle Multiplikation ein.

int faktor = 5;
ergebnis = 5 * ++faktor;
// faktor wird erst 6 -> 5 * 6 = 30
2. Postfix-Notation (faktor++ / faktor--)

„Zuerst mit altem Wert rechnen, danach ändern!“
Für die aktuelle Rechnung wird noch der alte Wert von faktor (5) benutzt. Erst danach erhöht sich faktor im Speicher auf 6.

int faktor = 5;
ergebnis = 5 * faktor++;
// Rechnet 5 * 5 = 25 (danach ist faktor = 6)

A10/12 Schritt-für-Schritt-Lösung der Code-Rätsel aus Aufgabe 10 und Aufgabe 12

Aufgabe 10 Ausgabe: 36 
int a = 2;
int b = ++a;   // Präfix: a wird 3, b wird 3
int c = 2 * b; // c = 2 * 3 = 6
c *= c;        // Kurz für c = c * c -> 6 * 6 = 36
System.out.println(c); // Gibt 36 aus
Aufgabe 12 (Block 1) Ausgabe: 109 
int a = 10;
int b = 12;
int c = a++ * --b;     // a++ nutzt 10 (a wird 11)
                       // --b senkt b sofort auf 11
                       // c = 10 * 11 = 110
System.out.println(--c); // --c senkt 110 sofort auf 109!
Aufgabe 12 (Block 2) Ausgabe: 30 
int c = 7;
c = --c * --c;         // Links: --c senkt c von 7 auf 6
                       // Rechts: --c senkt c von 6 auf 5
                       // Rechnung: 6 * 5 = 30
System.out.println(c); // Gibt 30 aus
Aufgabe 12 (Block 3) Ausgabe: Fehler! 
int c = 7;
c *= --7; // ❌ COMPILER-FEHLER!
System.out.println(c);

Begründung: Der Dekrement-Operator -- verändert den Wert einer Speicherzelle. Er kann nur auf echte Variablen (wie --c) angewendet werden, niemals auf ein festes Zahlen-Literal wie 7 (eine 7 kann man nicht auf 6 umbiegen)!
