Kontrollstrukturen in Java: Sequenz, Selektion & Iteration

Ohne Kontrollstrukturen würde jedes Computerprogramm stur Zeile für Zeile von oben nach unten durchlaufen und sich sofort beenden. Kontrollstrukturen (Steuerstrukturen / Kontrollanweisungen) definieren die Reihenfolge, in der Anweisungen ausgeführt werden, und bilden die Grundpfeiler der strukturierten Programmierung. Wie du bereits aus dem Modul Systementwicklung (PAP & Nassi-Shneiderman-Struktogramme) sowie aus Python oder PHP kennst, baut jeder Algorithmus der Welt auf genau drei Grundbausteinen auf: Sequenz, Selektion und Iteration.

Ausgangssituation • Strukturierte Programmierung

1. Die drei grundlegenden Kontrollstrukturen im Überblick

PAP & Struktogramm

1966 bewiesen die Informatiker Böhm und Jacopini mathematisch, dass sich absolut jedes Programmierproblem ohne unübersichtliche Sprungbefehle (goto) lösen lässt, wenn eine Programmiersprache diese drei Kontrollstrukturen beherrscht:

Grundstruktur 1

➡️ Sequenz (Abfolge)

Die lineare, streng aufeinanderfolgende Abarbeitung von Befehlen von oben nach unten. Jede Anweisung wird genau einmal ausgeführt, sobald die vorherige abgeschlossen ist (z. B. Variable deklarieren → Wert berechnen → Ergebnis ausgeben).

Grundstruktur 2

🔀 Selektion (Auswahl)

Eine Programmverzweigung anhand einer Bedingung. Je nachdem, ob eine Prüfung true (Ja) oder false (Nein) ergibt, schlägt das Programm einen anderen Weg ein. Man unterscheidet Einfachselektion (if), Zweifachselektion (if-else) und Mehrfachselektion (else-if / switch).

Grundstruktur 3

🔁 Iteration (Schleife)

Das wiederholte Ausführen eines Anweisungsblocks, solange eine Bedingung erfüllt ist. Man unterscheidet kopfgesteuerte Schleifen (while), fußgesteuerte Schleifen (do-while) und Zählschleifen (for).

Kapitel 2.4 (Seiten 1 bis 6)

2. Selektion in Java: If-Abfragen & Mehrfachauswahl

Entscheidungen

Bei einer Selektion prüft Java in runden Klammern (...) einen Ausdruck, der zwingend einen Wahrheitswert (boolean) liefern muss. Hier sind alle Varianten aus Kapitel 2.4 im Überblick:

1. Einfach- & Zweifachselektion (if / if-else)

Bei einer einfachen if-Abfrage wird der Block nur ausgeführt, wenn die Bedingung true ist. Fügt man einen else-Zweig hinzu (Zweifachselektion), wird garantiert einer der beiden Blöcke ausgeführt (Entweder-Oder). 

int alter = 19;

if (alter >= 18) {
    System.out.println("Zutritt erlaubt (Volljährig).");
} else {
    System.out.println("Zutritt verweigert!");
}

2. Mehrfachselektion (else if & switch-case)

Gibt es mehr als zwei Möglichkeiten (z. B. Schulnoten 1 bis 6), prüft man mit einer else if-Kaskade nacheinander mehrere Bedingungen oder nutzt für feste Werte ein switch-case-Konstrukt (wichtig: break; am Ende jedes Cases nicht vergessen!). 

int note = 2;

switch (note) {
    case 1: System.out.println("Sehr gut"); break;
    case 2: System.out.println("Gut");      break;
    default: System.out.println("Andere Note");
}
Kapitel 2.5 (Seiten 1 bis 13)

3. Iteration in Java: Die drei Schleifentypen im Vergleich

Wiederholungen

Schleifen wiederholen einen Codeblock (den sogenannten Schleifenrumpf), solange eine Laufbedingung erfüllt ist. In jeder IHK-Prüfung musst du den Unterschied zwischen kopfgesteuerten, fußgesteuerten und Zählschleifen sicher beherrschen:

Schleifentyp Steuerungsart & Mindestdurchläufe Wann setzt man sie ein? Java-Syntax (Beispiel)
1. while-Schleife
(Solange-Schleife)		 Kopfgesteuert 0 bis $\infty$ Durchläufe
(Prüft vor dem 1. Durchlauf) 		Wenn vorab nicht bekannt ist, wie oft die Schleife laufen muss (z. B. Datei Zeilenweise einlesen) und es sein kann, dass sie gar nicht betreten werden soll. int i = 0;
while (i < 3) {
  System.out.println(i);
  i++;
}
2. do-while-Schleife
(Wiederhole-bis)		 Fußgesteuert Mindestens 1 Durchlauf!
(Prüft erst am Ende) 		Perfekt für Benutzereingaben oder Konsolen-Menüs: Man muss den Nutzer zuerst mindestens einmal nach einer Eingabe fragen, bevor man prüfen kann, ob sie gültig war. Wichtig: Semikolon hinter while(...);! int zahl;
do {
  zahl = readInt();
} while (zahl <= 0);
3. for-Schleife
(Zählschleife)		 Kopfgesteuert (Zähler) 0 bis $n$ Durchläufe
(Start; Bedingung; Schritt) 		Immer dann, wenn die Anzahl der Durchläufe feststeht (z. B. „Laufe genau 10-mal“ oder „Gehe alle Elemente eines Arrays von Index 0 bis Ende durch“). for (int i = 1; i <= 5; i++) {
  System.out.println(i);
}
🛑 break; (Schleife komplett abbrechen)

Beendet die gesamte Schleife sofort und springt zur ersten Codezeile hinter der schließenden geschweiften Klammer der Schleife (z. B. wenn ein gesuchtes Element gefunden wurde).

⏭️ continue; (Aktuellen Durchlauf überspringen)

Bricht nur den aktuellen Schleifendurchlauf an dieser Stelle ab und springt direkt hoch zum nächsten Schleifendurchlauf.

4. Praxis-Umsetzung: Verschachteltes Struktogramm „Schaltjahr“

Struktogramm → Java

In der Zusatzaufgabe ist ein Nassi-Shneiderman-Struktogramm vorgegeben, das eine Jahreszahl einliest und über drei ineinander verschachtelte Selektionen prüft, ob ein Schaltjahr vorliegt. Wichtiger Unterschied zu LA 05: Während wir in LA 05 eine flache if - else if - else-Kette von 400 nach 4 geprüft haben, schreibt dieses Struktogramm zwingend vor, zuerst jahr % 4 == 0 zu prüfen und im Ja-Zweig (Y) weiter in die Tiefe zu verzweigen!

Musterlösung in Java (1:1-Übersetzung der Struktogramm-Verschachtelung)

Damit dein Code sowohl mit der Methode readInt() aus euren Schulungsunterlagen als auch im Standard-Java (über java.util.Scanner) direkt in Eclipse ausführbar ist, sind im folgenden Programm beide Varianten integriert:

SchaltjahrStruktogramm.java (Zusatzaufgabe LA 07) Java 
package kontrollstrukturen;

import java.util.Scanner;

public class SchaltjahrStruktogramm {

    // Hilfsmethode readInt() analog zu den Schulungsunterlagen:
    public static int readInt() {
        Scanner scanner = new Scanner(System.in);
        System.out.print("Bitte eine Jahreszahl eingeben: ");
        return scanner.nextInt();
    }

    public static void main(String[] args) {

        // 1. Sequenz: Lese eine Zahl "jahr" ein
        int jahr = readInt();

        // 2. Äußere Selektion: Ist die Zahl durch 4 teilbar?
        if (jahr % 4 == 0) {

            // Y-Zweig (durch 4 teilbar) -> Mittlere Selektion: Durch 100 teilbar?
            if (jahr % 100 == 0) {

                // Y-Zweig (durch 100 teilbar) -> Innere Selektion: Durch 400 teilbar?
                if (jahr % 400 == 0) {
                    System.out.println("Schaltjahr!");       // z. B. 2000
                } else {
                    System.out.println("Kein Schaltjahr!");  // z. B. 1900, 2100
                }

            } else {
                // N-Zweig von 100 (durch 4, aber NICHT durch 100 teilbar):
                System.out.println("Schaltjahr!");           // z. B. 2024, 2028
            }

        } else {
            // N-Zweig von 4 (nicht durch 4 teilbar):
            System.out.println("Kein Schaltjahr!");          // z. B. 2026
        }
    }
}

5. Offizielle Normen: PAP (DIN 66001) & Struktogramm (DIN 66261)

Prüfungswissen Normen
DIN 66261 Nassi-Shneiderman-Diagramm

Struktogramme zur Darstellung von Algorithmen

1972 von Isaac Nassi und Ben Shneiderman entwickelt und in Deutschland über die DIN 66261 genormt. Da Struktogramme keine freien Verbindungspfeile kennen, sondern Blöcke ineinander verschachteln, lassen sich damit ausschließlich sauber strukturierte Programme (ohne Spaghetticode/Goto-Sprünge) modellieren.

DIN 66001 Programmablaufplan (PAP)

Flussdiagramme mit genormten Symbolen

Die DIN 66001 normiert die grafischen Symbole eines Programmablaufplans: Abgerundetes Rechteck für Start/Stop, Parallelogramm für Ein-/Ausgabe (wie readInt()), Rechteck für Operationen (Sequenz) und die Raute (Rhombus) für Verzweigungen/Bedingungen (Selektion & Iteration).
