Klassen, Eigenschaften & Methoden in Java

Aus den vorangegangenen Lernaufträgen kennen wir bereits den Grundaufbau einer Klasse und wissen, wie Eigenschaften (Attribute) mit Datentypen definiert werden. Doch erst durch Methoden erwachen Objekte zum Leben: Während Attribute beschreiben, was ein Objekt ist oder hat (z. B. name, lebenspunkte, kontostand), legen Methoden fest, was ein Objekt tun kann (sein Verhalten). In diesem Lernauftrag analysieren wir alle Bestandteile einer Methodendeklaration – von Zugriffsmodifiern über Rückgabewerte und Getter/Setter bis hin zu Variablen-Scopes und Method Overloading.

🏗️ Anatomie einer Methode Kapitel 2.7 & 5.3: Methodenkopf, Signatur, Parameterliste, Rückgabetypen (inkl. void) und Namenskonventionen.
🔒 Kapselung & Modifier Kapitel 3.3 & 6: Sichtbarkeiten (public, protected, private), static, final sowie sichere Getter & Setter.
🎯 Scope & Overloading Gültigkeitsbereiche lokaler Variablen im Arbeitsspeicher und das Überladen gleichnamiger Methoden mit verschiedenen Parametern.
Kapitel 2.7 & 5.3 (Aufgaben 1, 3, 4 & 5)

1. Grundaufbau einer Methode, Bezeichner & Rückgabewerte

Methodendeklaration

F1 Formulieren Sie den Grundaufbau einer Methode innerhalb einer Klasse

Jede Methode in Java steht innerhalb des Klassenrumpfs und besteht aus zwei Hauptteilen: dem Methodenkopf (Header), der die Schnittstelle nach außen definiert, und dem Methodenrumpf (Body) in geschweiften Klammern { ... }, der die eigentlichen Programmierbefehle enthält:

Allgemeine Syntax-Schablone einer Methode Java Syntax 
// Allgemeiner Aufbau:
[Zugriffsmodifier] [static/final] Rückgabetyp methodenName(Datentyp parameter1, Datentyp parameter2) {
    // Methodenrumpf (Anweisungen / lokale Berechnungen)
    return ergebnisWert; // Nur nötig, wenn Rückgabetyp NICHT void ist
}

F4 Welche Regeln gibt es für Methodenbezeichner?

Für die Benennung einer Methode gelten sowohl die zwingenden Compiler-Regeln für Java-Bezeichner als auch die Java Naming Conventions für sauberen Code:

⚖️ Harte Compiler-Regeln (Syntax)
  • Darf nicht mit einer Ziffer beginnen (1berechne() ist verboten, berechne1() ist erlaubt).
  • Darf keine Leerzeichen oder Rechenzeichen (wie -, +, /) enthalten.
  • Erlaubt sind Buchstaben, Ziffern, Unterstrich (_) und Dollarzeichen ($).
  • Darf kein reserviertes Java-Schlüsselwort sein (z. B. nicht while() oder class()).
✨ Konventionen (Best Practices)
  • lowerCamelCase: Methoden beginnen immer mit einem Kleinbuchstaben. Jedes weitere zusammengesetzte Wort beginnt groß (z. B. berechneBruttoPreis()).
  • Sprechende Verben (Tätigkeitswörter): Da Methoden Aktionen ausführen, benennt man sie mit Verben (z. B. speichereDaten(), pruefePasswort(), getName()).

F3 Welche Möglichkeiten für Rückgabewerte gibt es?

Eine Methode kann in Java nach getaner Arbeit über den Befehl return genau einen Rückgabewert an den Aufrufer zurückliefern. Dafür gibt es drei Möglichkeiten:

  • 1. Primitive Datentypen: Alle 8 elementaren Typen wie int, double, boolean oder char (z. B. public boolean istVolljaehrig()).
  • 2. Komplexe Referenzdatentypen (Objekte & Arrays): Jede beliebige Klasse wie String, eigene Objekte (z. B. Kunde), Listen oder Arrays (z. B. int[]), wenn man mehrere Werte gebündelt zurückgeben möchte.
  • 3. Kein Rückgabewert (void): Wenn die Methode nichts zurückgibt (siehe Frage 5).

F5 Was bedeutet der Rückgabewert void?

Das englische Wort void bedeutet „leer“ bzw. „Leere“. Steht im Methodenkopf void anstelle eines Datentyps, führt die Methode zwar ihre Befehle aus (z. B. etwas auf der Konsole ausgeben oder ein Attribut ändern), gibt aber keinen Ergebniswert an den Aufrufer zurück.

Wichtig für den Code: Eine void-Methode benötigt am Ende kein return-Statement. Man darf jedoch ein leeres return; (ohne Wert dahinter) nutzen, um die Methode vorzeitig abzubrechen.

2. Zugriffsmodifier, final & statische Methoden (static)

Sichtbarkeit & Klassenebene

F2 Was bedeuten die Modifier public, protected, private, static und final?

In Java unterscheidet man zwischen Sichtbarkeits-Modifiern (Access Modifiers), die regeln, wer von außen auf eine Klasse, ein Attribut oder eine Methode zugreifen darf, und Verhaltens-Modifiern (Non-Access Modifiers) wie static und final:

Zugriffsmodifier Eigene Klasse Gleiches Package Unterklasse (Vererbung) Überall (Alle Klassen) Bedeutung & typischer Einsatz
public ✅ Ja ✅ Ja ✅ Ja ✅ Ja Öffentlich: Von überall im gesamten Projekt aufrufbar (Standard für Schnittstellen-Methoden, Getter/Setter und main).
protected ✅ Ja ✅ Ja ✅ Ja ❌ Nein Geschützt: Sichtbar im selben Package sowie in allen erbenden Kindklassen (Unterklassen) – auch wenn diese in einem anderen Package liegen.
(kein Modifier)
package-private		 ✅ Ja ✅ Ja ❌ Nein ❌ Nein Paket-Sichtbarkeit (Default): Wenn man gar nichts hinschreibt, ist das Element nur innerhalb desselben Packages (Ordners) sichtbar.
private ✅ Ja ❌ Nein ❌ Nein ❌ Nein Streng privat: Zugriff ist ausschließlich innerhalb derselben Klasse erlaubt! Standard für Attribute (Datenkapselung) und interne Hilfsmethoden.
static Klassen-Modifier

Bindet ein Attribut oder eine Methode fest an die Klasse als Ganzes statt an einzelne Objekte (Instanzen). Ein static-Element existiert im Speicher genau ein einziges Mal, egal ob 0 oder 1.000 Objekte der Klasse erzeugt wurden.

final Unveränderlichkeits-Modifier

Bedeutet „endgültig / unveränderbar“ und hat je nach Einsatzort drei Wirkungen:
• Bei Variablen/Attributen: Macht sie zur Konstante (Wert kann nur einmal zugewiesen werden, z. B. final double MWST = 0.19;).
• Bei Methoden: Verhindert, dass Unterklassen die Methode überschreiben (Overriding-Schutz).
• Bei Klassen: Verhindert, dass man von dieser Klasse erben kann (z. B. ist String in Java final).

F6 Was sind statische Methoden (static) im Detail?

Normalerweise muss man von einer Klasse zuerst mit dem Schlüsselwort new ein konkretes Objekt erzeugen, um deren Methoden aufzurufen (Instanzmethode). Statische Methoden (Klassenmethoden) tragen das Schlüsselwort static im Methodenkopf und gehören direkt zum Bauplan (der Klasse) selbst:

  • Aufruf ohne Objekt: Man ruft sie direkt über den Klassennamen auf: Klassenname.methodenname(). Bekannteste Beispiele sind die Mathematik-Methoden wie Math.round(3.7) oder Math.sqrt(25) sowie unsere public static void main(String[] args)-Methode (die beim Programmstart aufgerufen werden muss, wenn noch gar kein Objekt existiert).
  • Einschränkung im Speicher: Da eine statische Methode keinem bestimmten Objekt gehört, kennt sie keinen this-Zeiger und kann nicht direkt auf normale (nicht-statische) Objektattribute zugreifen!
Vergleich: Statische Methode vs. Objektmethode (Instanzmethode) Java 
public class Taschenrechner {
    // 1. STATISCHE METHODE (mit 'static'): Braucht kein Objekt!
    public static int addiere(int a, int b) {
        return a + b;
    }

    // 2. NORMALE OBJEKTMETHODE (ohne 'static'): Braucht ein Objekt mit 'new'!
    public void zeigeModell() {
        System.out.println("Casio FX-991");
    }

    public static void main(String[] args) {
        // Aufruf der statischen Methode direkt über den Klassennamen:
        int summe = Taschenrechner.addiere(10, 25);

        // Aufruf der Objektmethode erfordert vorherige Objekterzeugung mit 'new':
        Taschenrechner meinRechner = new Taschenrechner();
        meinRechner.zeigeModell();
    }
}

3. Getter & Setter: Kontrollierter Zugriff auf Attribute

Datenkapselung

F7 Was sind Getter und Setter und zu welchem Zweck werden sie erstellt?

In der professionellen objektorientierten Programmierung macht man die Attribute (Eigenschaften) einer Klasse niemals public, sondern schützt sie mit dem Modifier private vor direktem Fremdzugriff von außen (Prinzip der Datenkapselung / Information Hiding). Damit andere Klassen die Werte trotzdem kontrolliert auslesen oder ändern können, stellt man öffentliche Zugriffsmethoden bereit:

📖 Der Getter (Lese-Methode: get...)

Ein Getter dient dazu, den aktuellen Wert eines privaten Attributs nach außen hin abzufragen (auszulesen). Er hat denselben Rückgabetyp wie das Attribut, nimmt keine Parameter entgegen und gibt einfach return this.attribut; zurück (bei boolean-Attributen nennt man ihn oft is... statt get...).

✏️ Der Setter (Schreib-Methode: set...)

Ein Setter dient dazu, den Wert eines privaten Attributs von außen gezielt zu verändern (neu zu setzen). Er hat den Rückgabetyp void und nimmt den neuen Wert als Parameter entgegen.

🎯 Welchen Zweck verfolgt man mit Gettern und Settern? (Warum nicht einfach public Attribute?)
  1. Validierung & Plausibilitätsprüfung (Türsteher-Prinzip): Wäre ein Attribut lebenspunkte oder alter öffentlich (public), könnte jeder Programmierer von außen spieler.lebenspunkte = -999; reinschreiben. Ein Setter wirkt wie ein Türsteher: Er kann den übergebenen Wert mit einer if-Bedingung prüfen und ungültige Werte ablehnen oder korrigieren!
  2. Gezielte Zugriffssteuerung (Read-Only): Wenn ein Attribut (wie eine kontoNummer oder spielerId) von außen zwar gelesen, aber niemals überschrieben werden darf, programmiert man einfach nur einen Getter und lässt den Setter weg.
  3. Leichte Wartbarkeit: Ändert sich später die interne Speicherung in der Klasse (z. B. Preis wird intern plötzlich in Cent statt Euro gespeichert), muss man nur den Code im Getter/Setter anpassen, ohne dass fremde Klassen umgeschrieben werden müssen.
SpielerCharakter.java (Praxisbeispiel: private Attribute + Getter & Setter mit Schutzlogik) Java 
public class SpielerCharakter {

    // 1. Attribute sind streng 'private' (von außen nicht direkt manipulierbar!)
    private String name;
    private int lebenspunkte = 100;

    // 2. GETTER für 'name' (Lesezugriff)
    public String getName() {
        return this.name;
    }

    // 3. SETTER für 'name' (Schreibzugriff mit Prüfung auf leeren Text)
    public void setName(String neuerName) {
        if (neuerName != null && !neuerName.isEmpty()) {
            this.name = neuerName;
        }
    }

    // 4. GETTER für 'lebenspunkte'
    public int getLebenspunkte() {
        return this.lebenspunkte;
    }

    // 5. SETTER für 'lebenspunkte' mit Türsteher-Logik (0 bis max. 100 LP)
    public void setLebenspunkte(int neueLp) {
        if (neueLp < 0) {
            this.lebenspunkte = 0;   // Schutz: Keine negativen Lebenspunkte möglich!
        } else if (neueLp > 100) {
            this.lebenspunkte = 100; // Schutz: Maximalwert 100 nicht überschreiten!
        } else {
            this.lebenspunkte = neueLp;
        }
    }
}

4. Lokale Variablen (Scope) & Methoden-Überladung (Overloading)

Gültigkeit & Polymorphie

F8 Wie ist der Zugriff auf „lokale“ Variablen geregelt und was bedeutet „Scope“?

Variablen, die innerhalb einer Methode (oder in deren Parameterliste) deklariert werden, nennt man lokale Variablen. Im Gegensatz zu den Attributen einer Klasse dienen sie nur als kurzlebige Zwischenspeicher für eine Berechnung:

🔐 Wie ist der Zugriff auf lokale Variablen geregelt?
  • Streng lokal isoliert: Auf eine lokale Variable kann ausschließlich innerhalb genau der Methode (bzw. des Klammerblocks { ... }) zugegriffen werden, in der sie erstellt wurde.
  • Keine Zugriffsmodifier: Da andere Methoden oder Klassen sie ohnehin niemals sehen können, darf man vor lokale Variablen kein public oder private schreiben.
  • Lebensdauer: Sie entstehen beim Aufruf der Methode im Arbeitsspeicher (Stack) und werden sofort gelöscht, sobald die Methode am Ende ihrer schließenden Klammer } ankommt.
🔭 Was bedeutet der Begriff „Scope“?

Der englische Fachbegriff Scope bedeutet Gültigkeits- und Sichtbarkeitsbereich einer Variablen im Programmcode.

Faustregel für den Scope in Java: Eine Variable ist immer ab der Zeile ihrer Deklaration bis exakt zum Ende des umschließenden Anweisungsblocks (also bis zur nächsten zugehörigen schließenden geschweiften Klammer }) gültig und sichtbar. Man unterscheidet:
1. Klassen-/Objekt-Scope (Attribute: in der ganzen Klasse sichtbar)
2. Methoden-Scope (Lokale Variablen: nur in dieser Methode sichtbar)
3. Block-Scope (z. B. int i in einer for-Schleife: nur in der Schleife sichtbar).

F9 Was bedeutet „Overloading“ (Überladen) im Zusammenhang mit Methoden?

Unter Method Overloading (Überladen von Methoden) versteht man die Möglichkeit, innerhalb derselben Klasse mehrere Methoden mit exakt demselben Methodennamen anzulegen. Damit der Java-Compiler beim Aufruf genau weiß, welche Version der Methode gemeint ist, müssen sich die Methoden zwingend in ihrer Parameterliste unterscheiden:

✅ 1. Anzahl der Parameter Eine Methode nimmt 2 Parameter an, die gleichnamige Schwester-Methode nimmt 3 Parameter an (z. B. addiere(int a, int b) vs. addiere(int a, int b, int c)).
✅ 2. Datentypen der Parameter Beide nehmen 2 Parameter an, aber mit unterschiedlichen Typen (z. B. addiere(int a, int b) vs. addiere(double a, double b)).
❌ Prüfungsfalle Rückgabetyp! Nur den Rückgabetyp zu ändern (z. B. int berechne(int x) und double berechne(int x)) reicht NICHT zum Überladen und führt zu einem Compiler-Fehler!
OverloadingUndScopeDemo.java (Praxisbeispiel zu Aufgabe 8 & 9) Java 
public class OverloadingUndScopeDemo {

    // Klassen-Attribut (Klassen-Scope: in allen Methoden dieser Klasse sichtbar)
    private String waehrung = "EUR";

    // --- OVERLOADING: 3 Methoden mit demselben Namen 'berechnePreis' ---

    // Variante 1: Nur Grundpreis (1 Parameter: double)
    public double berechnePreis(double grundpreis) {
        double mwstFaktor = 1.19; // Lokale Variable (Scope: nur in Variante 1 gültig!)
        return grundpreis * mwstFaktor;
    }

    // Variante 2: Grundpreis + Stückzahl (2 Parameter: double, int)
    public double berechnePreis(double grundpreis, int stueckzahl) {
        // Hier wäre 'mwstFaktor' aus Variante 1 unbekannt (außerhalb des Scopes)!
        return (grundpreis * stueckzahl) * 1.19;
    }

    // Variante 3: Grundpreis + Stückzahl + Rabatt (3 Parameter: double, int, double)
    public double berechnePreis(double grundpreis, int stueckzahl, double rabattEuro) {
        double zwischensumme = (grundpreis * stueckzahl) - rabattEuro;
        return zwischensumme * 1.19;
    }
}

5. Wichtige OOP-Konzepte: Geheimnisprinzip & Methodensignatur

Prüfungswissen OOP
Information Hiding Geheimnisprinzip (David Parnas)

Warum Attribute fast immer private sind

Das Geheimnisprinzip (Information Hiding) besagt, dass eine Klasse ihre internen Datenstrukturen vor der Außenwelt verstecken soll. Andere Klassen dürfen nur über klar definierte Methoden (Getter/Setter/Fachmethoden) mit dem Objekt kommunizieren. Das verhindert unkontrollierte Seiteneffekte in großen Softwareprojekten.

Methodensignatur Java Language Specification (JLS)

Was genau gehört zur Signatur einer Methode?

In der IHK-Prüfung wird gerne gefragt: „Woraus besteht die Signatur einer Methode in Java?“
Offizielle Antwort: Ausschließlich aus dem Methodennamen und der geordneten Liste der Parameter-Datentypen (z. B. berechnePreis(double, int)). Zugriffsmodifier (public) und Rückgabetyp (double) gehören laut Java-Spezifikation nicht zur Signatur!
